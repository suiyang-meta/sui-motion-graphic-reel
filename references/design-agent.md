# 设计 agent：出三套 design system 给用户选

用户没有自己的 design system 时，由一个**只做这件事**的 agent 出方案（SKILL.md §1C）。下面是派工单、做法、交回格式。开不了第二个 agent 就自己照做，产出一样。

## 派工单（主 agent 填好交给设计 agent）

```
你是设计 agent。只做一件事：替这支片出 3 套 design system 方向，各附一张样张，交回给我。
不要写稿、不要做动画、不要替用户选。

【这支片】要讲什么、重点那一句话：
【画布】尺寸、帧率、片长、放哪个平台：
【用户过一轮的回答】气质 / 一定要用的颜色 / 角色 / 配音 / 给谁看：
【用户交的参考】每个参考的连结或图，加他说喜欢它的什么（只有一句形容也照写）：
【一定要的】品牌色、logo、指定字体…没有就写没有
【一定不要的】用户明讲过的…没有就写没有
【字体限制】只能用这台机器已有的 / 可以用免费可商用的网页字体 / 用户有买的字体：
【样张要画的内容】一句标题（这支片真的会出现的那一句）+ 一个主角物件 + 一行小字
【交到哪】放方案档与样张的资料夹：
【第几轮】第 1 轮。第 2 轮起写：上一轮三套各被说了什么
```

## 设计 agent 怎么做

1. **先读参考，写下它的语言**：几个颜色、平涂还是有质感、字的性格、版面靠什么对齐、东西怎么动。学语言，不抄画面。用户只给了一句形容（「干净、有呼吸感」）也一样：写下你把这句话读成什么画面特征，放进交回档，让用户看你有没有读对。
2. **三套要拉得开**。常用的拉法如下，可以只用一种（三套各站一端），也可以叠两种；交回时每套标一句它站在哪一端：
   - 深底 ／ 浅底 ／ 有质感的底（纸、颗粒、照片）
   - 几何冷静 ／ 手作温暖 ／ 鲜明活泼
   - 贴着参考走 ／ 参考的反面 ／ 从题材里长出来的第三条路
3. **每套的签名元素从题材长出来**：这个题材的人平常会看到什么记号、表格、工具、材质？（设计软件的把手与轨道、冲泡记录的刻度与时间戳、运动 App 的计时环、打卡格…）
4. **先定主角物件，再画**。三套画的是**同一个东西**，画法可以各套不同。定之前先问：这个东西缩成手机上一张小图，认得出是什么吗？认不出（例：俯视的瑜伽垫像一个罐子）就换一个认得出的角度或换一个物件。主角选错，三套一起吃亏。
5. **每套写完过一遍**：
   - 字在底色上读得清楚，小字不小于 24px。
   - 三色以内讲得完；要第四色就写理由。两色叠印或网点自然混出来的颜色不另算，但要写明是叠出来的。
   - 「不要」清单写的是看得出来的东西，不是形容词。用户给的「一定不要的」对三套都算数，写在交回档最上面一次，不用每套重抄；每套只写它自己多出来的「不要」。
   - 平台介面会盖住的上下区域不放要读的东西，签名元素里要读的字也算。数字照那个平台现在的介面量；没量过就先上方留约八分之一、下方留约五分之一，并标明是估计。
6. **画样张**：三套用同一句标题、同一个主角物件、同一行小字，各画一张静态画面（照这支片的画布尺寸），版面骨架与签名元素都要画出来。
   - 怎么渲染：一套一页 HTML，用无头浏览器照画布尺寸截成图（本机的 Chrome / Edge 无头模式、Playwright 都行）。做片引擎自己的截图指令多半要先有一个专案，单张样张不必走它。
   - 三张横排拼成一张并排图，每张上方标 A / B / C、名字、站在哪一端。
7. **把图读进来自己看**，逐张查：
   - 三套有没有两套太像（同样的底色明度、同样的主角颜色与摆法都算像）。
   - 字读得清吗、有没有贴边或出安全边。
   - 主角物件认得出吗。
   - 有没有踩到「一定不要的」。
   - 不行就改到行，再截一次。
8. 不替用户选。可以写一句「我会选哪一套、为什么」，放在最后，明讲是建议。

## 交回格式

```markdown
# design system 方案 · <专案名>（第 _ 轮）

样张（并排）：<路径>　　单张与原始 HTML：<资料夹>
画布：<尺寸 · 帧率 · 片长 · 平台>
用户一定不要的（三套都算数）：
我从参考读到的：<几句话；用户没给参考就写你把他的形容读成什么>

## A · <名字>（站在哪一端）
- 一句话：这一套让人觉得怎样
- 色板：底 #…… · 字 #…… · 强调 #……
- 质感：平涂 / 渐层 / 发光 / 颗粒 / 阴影，各写用或不用，用在哪
- 字：标题 … · 内文 … · 小字 …（写明字体从哪来、能不能商用）
- 版面骨架与安全边：
- 签名元素：
- 动的性格：
- 角色：
- 声音：
- 这一套多出来的不要：
- 适合 / 不适合：什么内容最好看、什么内容会吃亏

## B · <名字>（站在哪一端）
…

## C · <名字>（站在哪一端）
…

## 样张里还留着的毛病
（照实列：哪一张的什么东西只是示意、哪里还不够好）

## 建议（用户决定）
我会选 _，因为 _。也可以混搭：_ 的颜色配 _ 的字。
```

## 主 agent 拿到之后：怎么给用户选

- **把并排图直接给用户看**（贴在对话里或送档），再问他选哪一套。环境里有选择题工具就用选择题：三套各一个选项，选项里写那一套的一句话；另留「混搭 / 都不要」让他自己讲。
- 设计 agent 的建议可以附上，标明是建议。
- 整套选：把那一套照 `design-system.md` 的栏位写进专案根目录的 `design-system.md`，每一格标「用户选的」。
- 混搭：照他说的拼，拼完**再画一张样张**给他看一眼（混搭最容易出的问题是字在新底色上读不清）。
- 都不喜欢：问哪里不对（太冷、太花、太像别人…），带着这句话派第 2 轮。两轮还选不出来，请他给一个参考。
- 没被选的两套留着（样张与方案档），之后想换风格不用重来。
