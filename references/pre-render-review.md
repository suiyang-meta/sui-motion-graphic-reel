# 渲染前审片

出一整支片很慢，而且出完才发现的毛病，多半在出片之前就看得出来。这一步的目的：**用户会挑的毛病，在出片之前由 agent 先替他挑完。** 用户看到的第一版，应该已经过了他自己那一关。

替用户挑毛病，靠的是一份**审片习惯档**（`review-habits.md`）：他过去每一次看片挑出来的事，一条一条记在里面，下一支片开做时逐条先查。格式与怎么长大在 `review-habits.md`。

## 什么时候做

分镜点头之后、画面写完之后、**出整支片之前**。三层，便宜的先做：

| 层 | 看什么 | 花多少 | 抓得到 |
|---|---|---|---|
| ① 纸上审 | 分镜表、稿、design system | 不用跑任何东西 | 结构上的错：每幕做法重复、少层、焦点不只一个、开场没有两波、稿与主轴不合、数字对不上 |
| ② 机器量 | 几张静态截图 | 截图几秒到几十秒，不出片 | 量得出来的错：字出安全边、东西超出容器、对比不够、两拍画面几乎一样、该动的段落没在动、画面太空 |
| ③ 审片 agent 看图 | 停住帧原尺寸 + 连拍 + 习惯档 | 一个 agent 看十几张图 | 要用眼睛判的：主角认不认得出、俗不俗、干不干、物件崩了没、统不统一 |

三层都过才出片。出片之后还有 SKILL.md §6 的成片自审，管这三层管不到的：声音、连续动起来的手感、压缩后的样子。

## ① 纸上审

把习惯档里「什么时候查」写着**分镜**的每一条拿出来，对着分镜表逐条答「过 / 不过 / 这支片用不上」。不过的先改分镜，不要带着已知的毛病去写画面。

## ② 机器量

1. 用引擎的**单张截图**指令截图（不是出片）：
   - 每一拍主体停住的那一刻各一张。
   - 开场前 4 秒、每个转场、每段 3D 运镜：每 0.1–0.2 秒一张。
   - 一下就过的动作（标题落地、压扁回弹、盖章）：那半秒**每帧一张**。每 0.15 秒一张会刚好跳过它。
   - 档名带秒数，放进一个**干净的资料夹**（引擎可能顺手在同一夹写联络表）。
2. 引擎自己有检查指令就先跑（例：HyperFrames 的 `check` 会查语法、执行期错误、文字溢出容器、对比）。
3. 跑量测脚本：
   ```
   python3 scripts/preflight.py <截图资料夹> --stops <每拍停住的秒数> --bursts <要看动不动的区间> --safe <左,上,右,下>
   ```
   它出 `stops.jpg`（每拍停住帧并排、画上安全边框线）、每个区间的连拍、`report.md`（提醒清单）。
   引擎的检查可能大量误报：整个画面每帧重画的写法（SKILL.md §4⑧）会让它以为每个字只出现一瞬间。先分清哪一类是这种写法造成的，剩下的才逐条看。
4. `report.md` 的每一条提醒都回去看图判。机器只量得出「边上有东西」「两拍很像」「这段没在动」，量不出好不好看。

## ③ 审片 agent：替用户的眼睛看

让**另一个 agent** 看，不是做片的那个自己看。做片的 agent 知道每样东西「应该」是什么，会把崩掉的东西看成对的；审片的只看得到图，跟用户一样。开不了第二个 agent 就自己做，但要知道这样会漏：自己写的画面忘不掉，会把转场途中的格子扫过去。补救做法是倒过来看 —— **先只看连拍、逐格写「这一格的焦点是什么」，最后才看停住帧**；并且在交付时跟用户明讲「这一轮是做片的 agent 自己审的」。

派工单：

```
你是审片 agent。你替用户在出片之前先看一遍，把他会挑的毛病挑出来。
你只看图与下面给你的档，不看程式、不改任何东西、不替做片的人找理由。

【审片习惯档】<review-habits.md 的路径> —— 用户过去挑过的每一件事。这是你的眼睛。
【design system】<路径> —— 这支片说好只用什么。
【这支片要讲的那一句话】：
【图】停住帧原尺寸：<资料夹> · 并排：<stops.jpg> · 连拍：<burst-*.jpg> · 机器提醒：<report.md>
【每一拍】秒数 · 这一拍说好的焦点是什么（只给这一句，不给分镜的其他栏）

做法：
1. 先不看习惯档，把每一张停住帧原尺寸读进来，各写一句「我第一眼看到什么、这是什么东西」。
   认不出主角、不知道该看哪、看不懂在讲什么，照实写。
2. 再拿习惯档逐条查：每一条写 过 / 不过 / 这些图看不出来。
   不过的写：哪一秒、哪一张图、画面上的哪里、照习惯档那一条该是怎样。
3. 对 design system：有没有哪一张用了它以外的颜色、字、做法。
4. 连拍**每一格都看，不是只看停住帧**。转场途中的格子最容易被扫过去，而毛病多半在那里：
   - 每一格都说得出焦点是什么吗？有没有哪一格整片发白、空掉、或两幕的东西叠在一起？
   - 资讯列、标题有没有在某一格被别的东西压到？
   - 是不是真的每格都在变；3D 物件看不看得到侧面、有没有哪一格缺东西或穿模。
5. 最后列「习惯档里没有、但我觉得用户会挑」的，另外放一段，标明是你的判断。

交回：
- 必改（习惯档里标必改的条目没过）：逐条
- 建议改：逐条
- 看不出来、要等成片才知道的：逐条（这几条留给成片自审）
- 一句总评：现在出片，用户第一眼会说什么
```

做片的 agent 拿到之后：必改的全部改完，重截那几张图，再给审片 agent 看一次，过了才出片。**改一处，把它前后各 1 秒重截连拍再看**：修好一格、让隔壁空掉，是最常见的新毛病。

每一轮审片 agent 的交回都存成档（`pre-render-review-round1.md`、`round2`…）。没有一份「必改：无」的交回档，就不算过。最多来回三次；三次还有必改没过，停下来告诉用户卡在哪。

## 用户不在场也一样做

这一步本来就是替用户做的，他在不在都跑。交付时附上：审片 agent 最后一次的交回、三层各抓到什么改了什么、留给成片才看得出来的有哪些。

## 这一步抓不到的（照实）

- 声音：配音像不像讲话、有没有被切掉、音效与画面对不对。
- 连续播放的手感：节奏拖不拖、缓动顺不顺。连拍只看得出「有没有在动」。
- 用户还没挑过的新毛病。习惯档里没有的事，审片 agent 只能靠一般判断。所以每一次他挑出新的，都要记回去（见 `review-habits.md`「怎么长大」）。
